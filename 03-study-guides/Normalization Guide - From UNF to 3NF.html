DATABASE NORMALIZATION PROCESS

UNF, 1NF, 2NF and 3NF

Normalization stages and dependency analysis

What normalization does

Normalization evaluates and corrects table structures so each fact is stored in an appropriate place. It reduces repeated data and prevents insertion, update and deletion anomalies.

The route from UNF to 3NF

UNF

Repeating groups or report-style nested data remain.

1NF

One value per cell, one row per occurrence, and a key is identified.

2NF

1NF plus no partial dependencies on part of a composite key.

3NF

2NF plus no transitive dependencies between non-key attributes.
First make the data atomic for 1NF. Then check that every non-key attribute depends on the key, the whole key, and nothing but the key. This saying is not the definition of 1NF.

Step 0: Recognise UNF

The source report contains a repeating employee group inside each project. Blank report cells may visually mean “same project as above”; they are not complete relational rows.

Step 1: First Normal Form

Create one row for every project-employee assignment and identify the composite primary key.

1NF removes the repeating group, but it does not remove redundancy.

Functional Dependencies

  • Full: (Proj_Num, Emp_Num) -> Hours
  • Partial: Proj_Num -> Proj_Name
  • Partial: Emp_Num -> Emp_Name, Job_Class
  • Transitive: Job_Class -> Chg_Hour

Because partial dependencies remain, the relation is in 1NF but not 2NF. Chg_Hour is also transitively dependent on Emp_Num through Job_Class.

Step 2: Second Normal Form

Move facts controlled by only part of the composite key into their own relations.

PROJECT (Proj_Num, Proj_Name)
EMPLOYEE (Emp_Num, Emp_Name, Job_Class, Chg_Hour)
ASSIGNMENT (Proj_Num*, Emp_Num*, Hours)
The complete 2NF EMPLOYEE relation still contains both Job_Class and Chg_Hour. It is not yet 3NF.

Step 3: Third Normal Form

Create JOB for Job_Class -> Chg_Hour and retain Job_Class in EMPLOYEE as a foreign key.

PROJECT (Proj_Num, Proj_Name)
JOB (Job_Class, Chg_Hour)
EMPLOYEE (Emp_Num, Emp_Name, Job_Class*)
ASSIGNMENT (Proj_Num*, Emp_Num*, Hours)
The original report can be reconstructed by joining ASSIGNMENT to PROJECT and EMPLOYEE, then EMPLOYEE to JOB.

Exam Answering Strategy

Past papers commonly ask students to state the current normal form with reasons, write the relational schema and dependencies, and normalize through 3NF. Always follow the exact wording of the paper.

  1. Diagnose repeating groups and the current normal form.
  2. Propose the key and write full, partial and transitive dependencies.
  3. Write complete 1NF, 2NF and 3NF schemas.
  4. Underline each PK and mark every FK consistently.
